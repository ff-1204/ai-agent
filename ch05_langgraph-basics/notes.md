# 필기
## 랭그래프(LangGraph)
- 랭그래프는 다양한 에이전트 시스템을 설계하고 구현하기 위한 프레임워크로, 시스템의 로직을 노드와 엣지로 구성된 그래프로 표현하는 것이 특징이고, 시스템의 로직을 노드와 엣지로 구성된 그래프로 표현하는 것이 특징입니다.
- 랭그래프에서는 에이전트나 기능 단위는 '노드'로 노드 간의 실행 경로는 '엣지'로 나타냅니다. 그래프 구조로 작업 흐름을 연결하므로 경로가 복잡한 에이전트도 비교적 쉽게 설계할 수 있습니다. 단순히 흐름을 연결할 뿐 아니라, 반복이나 병렬 처리와 같은 복잡한 제어 흐름까지 명확하게 표현할 수 있어, 대규모 에이전트 시스템에서도 논리적 복잡성을 효과적으로 관리할 수 있습니다.
- 랭그래프는 '상태 관리'를 핵심 철학으로 삼아 설계되었습니다. 에이전트가 잡업을 수행하는 과정에서 발생하는 모든 중간 정보와 상태 변화가 그래프 내에서 관리되므로, 복잡한 에이전트 간 협업도 안정적으로 처리할 수 있습니다.
- 랭그래프는 LLM 애플리케이션 개발 프레임워크인 랭체인(LangChain) 생태계와 통합되어 있어, 랭체인 LLM 호출, 도구 사용, 메모리 등 이미 널리 사용되는 다양한 구성 요소를 그대로 활용하기에 좋습니다. 또한, 랭그래프는 사전에 구축된 에이전트를 제공합니다. 
- 랭그래프는 에이전트 시스템의 전체 동작 흐름을 그래프 구조로 표현하기 때문에 시스템을 직관적으로 설계하기 쉽습니다.
- 라마인덱스의 차이 넣어줘
- mermain 사용해서 표현 개선해줘.

### 랭그래프의 특징
- 그래프는 노드(node)와 엣지(edge)로 구성됩니다. 
  - 노드는 그래프를 이루는 기본 단위이며, 그래프를 어떻게 활용하느냐에 따라 사람, 장소, 사물 같은 개체(Entity)를 나타낼 수 있고, 작업 단계나 처리 과정처럼 행위 또는 절차를 표현할 수 있습니다.
  - 엣지는 노드와 노드의 연결을 나타냅니다. 이는 노드 사이의 관계를 표현하는데, 사람과 사람 사이의 관계(친구, 부모 등..)를 나타낼 수도 있고, 지역과 지역을 잇는 경로를 의미할 수 있습니다.
  엣지는 방향성을 가지고 있는 경우도 있고 없는 경우도 있습니다. 쉽게 말해 화살표로 연결되면 방향성이 있는 것이고, 그렇지 않으면 방향성이 없는 엣지입니다. 
    - 예를 들어 "철수는 영희를 좋아한다"라는 문장을 그래프로 표현하려면 '철수' 노드에서 시작하여 '영희' 노드로 끝나는 엣지가 연결되어야 하므로 방향성이 필요합니다. 그러나 "철수와 영희가 SNS 일촌이다"를 나타내고 싶다면 어느 한쪽만 일촌일 수는 없고 쌍방향 관계이기 떄문에 방향이 없는 엣지로 표현할 수 있습니다.
  - 이처럼 노드와 엣지를 사욯해 대상 간의 관계와 흐름을 구조적으로 표현한 형태를 그래프라고 합니다. 그렇다면 그래프 구조를 활용해 에이전트의 상태와 실행 흐름을 설계할 수 있는 랭그래프를 사용하면 어떤 장점이 있을까요?
- AI 에이전트는 여러 단계를 거쳐 문제르 해결하는 복잡한 작업 흐름을 수행합니다. 이때 각 단계를 세분화하고, 작업 간 순서와 조건을 명확히 정의할 수 잇는 구조가 필요합니다. 이러한 에이전트 시스템의 요구를 충족시키는 것이 바로 랭그래프입니다. 랭그래프는 작업 단계는 노드, 단계 간의 흐름은 엣지로 표현하여 복잡한 에이전트의 실행 과정을 시각적으로 논리적으로 구성할 수 있습니다. 또한 단계별 실행 상태를 추적하고 수정하기 용이해 유지 보수성과 확장성이 크게 향상됩니다.
- 복잡한 AI 에이전트 로직 구현
- 확장성 높은 사용자 맞춤 설계
- 그래프 분기 처리를 통한 유연한 제어
- 양반향 파이프라인 구성을 통한 성능 개선

### 랭그래프 기본 개념 이해하고 적용하기
#### 상태
- 상태(state)는 그래프, 즉 에이전트의 현재 상태를 나타내는 데이터 구조입니다. 쉽게 말해 에이전트가 작업을 수행하면서 지속적으로 관리해야 하는 정보라고 할 수 있는데요. 예를 들어 챗봇의 경우 사용자로부터 메시지를 받아야 하고, 그에 대한 결과 메시지를 에이전트가 변환해야 하므로 메시지를 관리하는 구조가 필요합니다. 이 경우 에이전트 그래프는 "message"라는 키(key)를 상태로 가지며, 이 키에 대응하는 값(value)으로 메시지 목록이 저장됩니다. 즉 챗봇이 동작하면서 누적되는 대화 기록을 지속적으로 관리할 수 있습니다.
 - 이처럼 상태 구조를 정의한 것을 그래프 스키마(Graph schema)라고 하며, 그래프 스키마 정의를 통해 에이전트 그래프가 사용자의 질문과 답변을 정해진 데이터 구조에 맞게 입력받고 반환하도록 보장할 수 있습니다. 또한 작업의 중간 결과도 이 상태에 지속적으로 업데이트됩니다.
 - 그래프 스키마는 주로 TypedDict 혹은 파이단틱(Pydantic)의 BaseModel을 통해 구현됩니다. 이를 통해 상태 스키마 필드의 데이터 타입을 정의할 수 있습니다.

#### 리듀서(reducer) 함수
- 리듀서(reducer) 함수는 그래프 상태에서 정의한 "message"는 새로운 값으로 덮어씌워져 매번 새로운 메시지가 들어 있는 리스트로 반환될 수 있지만, 기존 값을 유지하며 새로운 값이 추가된 형태로 관리될 수도 있습니다. 이때 상태의 업데이트 방식을 지정하는 것이 리듀서(reducer)함수 입니다.
