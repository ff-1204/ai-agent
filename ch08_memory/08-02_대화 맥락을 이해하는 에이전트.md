# 8.2 대화 맥락을 이해하는 에이전트

> **저자 예제** — [`examples/short-term memory.ipynb`](examples/short-term%20memory.ipynb)
> **공식 문서** — [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) · [Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)

> **여기까지** — 메모리가 **두 층**이라는 것까지 왔습니다([8.1절](08-01_AI%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%EC%97%90%EC%84%9C%20%EB%A9%94%EB%AA%A8%EB%A6%AC%EC%9D%98%20%EC%97%AD%ED%95%A0.md)).
> **이 절의 질문** — **단기 메모리(체크포인터)** 를 코드로 어떻게 붙이지?
> **다 읽으면** — 대화가 이어지는 챗봇을 만들 수 있습니다. **세 가지가 짝을 이뤄야** 한다는 것도 알게 됩니다.

## 8.2.1 [실습] 랭그래프에서 단기 메모리 사용하기

### 메시지 없이 먼저 확인합니다

저자 예제의 첫 코드가 아주 좋습니다. **LLM도 메시지도 없이** 체크포인터만 봅니다.

```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import StateGraph
from typing import Annotated
from operator import add

graph_builder = StateGraph(Annotated[int, add])     # 상태가 그냥 정수 하나

graph_builder.add_node("get_one", lambda x: 1)      # 항상 1을 반환
graph_builder.set_entry_point("get_one")
graph_builder.set_finish_point("get_one")

graph = graph_builder.compile(checkpointer=InMemorySaver())

result1 = graph.invoke(0, {"configurable": {"thread_id": "user1"}})
result2 = graph.invoke(0, {"configurable": {"thread_id": "user1"}})
result3 = graph.invoke(0, {"configurable": {"thread_id": "user1"}})
```

**세 번 다 `0`을 넣고 노드는 항상 `1`을 반환하는데, 결과가 매번 달라집니다.**

이유는 [5.2.2절](../ch05_langgraph-basics/05-02_%EB%9E%AD%EA%B7%B8%EB%9E%98%ED%94%84%20%EA%B8%B0%EB%B3%B8%20%EA%B0%9C%EB%85%90%20%EC%9D%B4%ED%95%B4%ED%95%98%EA%B3%A0%20%EC%A0%81%EC%9A%A9%ED%95%98%EA%B8%B0.md)의 **리듀서**입니다.

| 요소 | 하는 일 |
| :--- | :--- |
| `Annotated[int, add]` | 새 값을 **더한다** (덮어쓰지 않음) |
| `checkpointer=InMemorySaver()` | 호출이 끝나도 **상태를 남긴다** |
| `thread_id="user1"` | 다음 호출이 **그 상태를 이어받는다** |

**리듀서 + 체크포인터 + 같은 `thread_id`** 세 가지가 맞아떨어져야 누적됩니다. 하나라도 빠지면 매번 초기화됩니다.

```mermaid
graph LR
    A["1회차<br/>저장된 상태 없음"] --> B["2회차<br/>1회차 상태를 이어받음"]
    B --> C["3회차<br/>2회차 상태를 이어받음"]
```

> **이게 단기 메모리의 전부입니다.** 메시지든 정수든 원리가 같습니다. "대화를 기억한다"는 건 **상태가 이어진다**는 것뿐입니다.

### `thread_id`를 바꾸면 새 대화입니다

같은 그래프에 `thread_id="user2"`를 주면 상태가 처음부터 시작합니다. **`thread_id`는 저장 칸의 이름**입니다.

## 8.2.2 [실습] 챗봇에 단기 메모리 적용하기

이제 메시지로 같은 일을 합니다.

```python
class State(TypedDict):
    messages: Annotated[list, add_messages]      # 리듀서

def chatbot(state: State):
    return {"messages": [llm.invoke(state["messages"])]}

graph_builder = StateGraph(State)
graph_builder.add_node("chatbot", chatbot)
graph_builder.set_entry_point("chatbot")
graph_builder.set_finish_point("chatbot")

checkpointer = InMemorySaver()
graph = graph_builder.compile(checkpointer=checkpointer)     # 체크포인터
```

```python
graph.invoke(
    {"messages": [{"role": "user", "content": "안녕하세요! 제 이름은 공원나연입니다."}]},
    {"configurable": {"thread_id": "1"}},
)

graph.invoke(
    {"messages": [{"role": "user", "content": "제 이름이 뭐라고요?"}]},
    {"configurable": {"thread_id": "1"}},
)
```

**두 번째 호출에 이름이 안 들어 있는데 답할 수 있습니다.**

[2.3절](../ch02_core-elements/02-03_%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%EC%9D%98%20%EA%B8%B0%EC%96%B5%EB%A0%A5%20-%20%EB%A9%94%EB%AA%A8%EB%A6%AC.md)에서 손으로 그렸던 그림이 이것입니다. 우리가 다시 넣어 준 게 아니라 **체크포인터가 이어 준 것**입니다.

```python
def chatbot(state: State):
    return {"messages": [llm.invoke(state["messages"])]}
    #                                ^^^^^^^^^^^^^^^^^
    #                    이 안에 이전 대화가 이미 들어 있음
```

**노드 코드는 메모리를 전혀 모릅니다.** `compile(checkpointer=…)` 한 줄과 `thread_id` 하나가 전부입니다. 이게 랭그래프를 쓰는 이득입니다([5.1절](../ch05_langgraph-basics/05-01_%EC%99%9C%20%EB%9E%AD%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%B8%EA%B0%80.md)).

### 세 가지가 짝을 이룹니다

| 빠뜨리면 | 증상 |
| :--- | :--- |
| 리듀서(`add_messages`) | 새 메시지가 이전 것을 **덮어씀** — 이력이 안 쌓임 |
| `checkpointer=` | 호출이 끝나면 **상태가 사라짐** |
| `thread_id` | 어느 칸에서 이어받을지 몰라 **오류** |

> **`thread_id` 없이 체크포인터를 쓰면 오류가 납니다.** 체크포인터를 붙였으면 반드시 `config`를 함께 넘기세요.

### 어디까지 저장되나

체크포인터는 **메시지만이 아니라 상태 전체**를 저장합니다. [7.6절](../ch07_multi-agent/07-06_%EC%9E%90%EB%A3%8C%20%EC%A1%B0%EC%82%AC%20%EC%A0%84%EB%AC%B8%EA%B0%80%20%2B%20%EB%AC%B8%EC%84%9C%20%EC%9E%91%EC%84%B1%20%EC%A0%84%EB%AC%B8%EA%B0%80%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%23%ED%94%8C%EB%9E%98%EB%8B%9D%20%EA%B8%B0%EB%B0%98%20%EC%8A%88%ED%8D%BC%EB%B0%94%EC%9D%B4%EC%A0%80.md)의 `plan`·`past_steps` 같은 키도 함께 남습니다.

그래서 **긴 작업을 중단했다 재개**할 수 있습니다. [5.1절](../ch05_langgraph-basics/05-01_%EC%99%9C%20%EB%9E%AD%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%B8%EA%B0%80.md)에서 말한 "멈춘 자리에서 다시"가 이 저장 덕분입니다.

## 요약 및 비유

**같은 상담원에게 다시 전화하는 것**과 같습니다. 접수번호(`thread_id`)를 대면 **지난 통화 기록을 띄워** 이어서 이야기합니다. 번호를 안 대면 처음부터입니다.

| 개념 | 상담 전화 비유 | 기술적 의미 |
| :--- | :--- | :--- |
| **체크포인터** | 통화 기록 시스템 | 호출 간 상태 보존 |
| **`thread_id`** | 접수번호 | 저장 칸 이름 |
| **리듀서** | 기록에 덧붙여 적기 | `add_messages` |
| **리듀서 없음** | 기존 기록을 지우고 새로 | 덮어쓰기 |
| **정수 누적 예제** | 통화 횟수 세기 | 메시지 없이 원리 확인 |
| **노드가 메모리를 모름** | 상담원은 시스템을 신경 안 씀 | `compile` 한 줄로 처리 |
| **상태 전체 저장** | 통화 외 메모도 함께 | `plan` 등 다른 키도 |
| **`thread_id` 변경** | 새 번호로 접수 | 새 대화 |

## 결론

* 단기 메모리는 **리듀서 + 체크포인터 + 같은 `thread_id`** 세 가지가 맞아야 동작합니다. 하나만 빠져도 안 됩니다.
* 저자의 **정수 누적 예제**가 원리를 가장 잘 보여 줍니다. 메시지든 정수든 "상태가 이어진다"는 점은 같습니다.
* **노드 코드는 메모리를 전혀 모릅니다.** `compile(checkpointer=…)`와 `config`의 `thread_id`가 전부입니다.
* 체크포인터를 붙였으면 **`config`를 반드시 함께 넘겨야** 합니다.
* 체크포인터는 **메시지만이 아니라 상태 전체**를 저장합니다. 그래서 중단·재개가 됩니다(5.1절).
* `thread_id`를 바꾸면 **새 대화**입니다. 8.4절에서 이 성질을 이용해 장기 메모리와 대비시킵니다.
